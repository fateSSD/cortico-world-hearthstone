# 炉石陪打 · cortico-world-hearthstone

Coopani 的 World 扩展。她坐在旁边看你打炉石——知道你多少血、场上有什么、还剩几张牌、对面铺了几个随从,这手该解场还是该压,费够不够上那张大牌,对面有没有斩杀。在该开口的时候开口。

**只看,不动手。** 不模拟点击、不碰游戏进程、不替你出牌。

打完一局还能陪你复盘:哪一手走了岔路、她当时建议了什么、你实际打了什么。

## 她怎么看到对局

读炉石自己写的对局日志(`Power.log`),不开屏幕识别。这条路的好处是数字全是游戏自己给的,不会把「火球术」看成「寒冰箭」;代价是**必须先打开日志**。

日志里能拿到的:双方职业、生命值、护甲、场上每个随从的攻击力/生命/关键词(嘲讽、圣盾、冻结、潜行、风怒)、手牌张数、牌库张数、水晶、回合数、谁在行动、谁打了什么牌、谁攻击了谁、谁阵亡、胜负。

拿不到的:**对手手牌具体是哪几张**、卡牌的文字效果、动画演出。

## 前置:打开炉石的 Power 日志

在下面这个位置写入 `log.config`(没有就新建):

- **Windows**：`%LOCALAPPDATA%\Blizzard\Hearthstone\log.config`
- **macOS**：`~/Library/Preferences/Blizzard/Hearthstone/log.config`（安装目录那份不读，别放错）

内容:

```ini
[Power]
LogLevel=1
FilePrinting=true
ConsolePrinting=false
ScreenPrinting=false
```

然后**重启炉石**。启动后 `C:\Program Files (x86)\Hearthstone\Logs\<会话目录>\Power.log` 会开始写。

### 还要把 10MB 上限关掉

炉石给每份日志设了 10MB 的硬上限,到线就停笔(打印一句 `Truncating log, which has reached the size limit of 10000KB` 然后彻底不写)。一份日志大概装四局,打到第三、四局就失明,之后整局数据全丢。

**这个上限是炉石自己的一个配置项**,在安装目录的 `client.config`:

```ini
[Log]
FileSizeLimit.Int=-1
```

`-1` 是它自己的「无限制」。记牌器(HDT、Firestone)都会写这个键,所以它们从不撞这个问题。

扩展在启动时会自己检查并补上这一行(会先留一份 `client.config.bak`),但**炉石只在启动时读这个文件** —— 所以改完要再退一次炉石才生效。那之后就不会再为这件事打断你。

两条从外面绕的路都试过,都不行,别再试:

- **裁短文件**:炉石以独占方式打开日志(不共享写),`open(path,'r+b')` 直接 `Permission denied`,整个会话不放句柄
- **就算能裁**:它记着自己的写偏移,文件变短之后下一次写会定位回原位,中间变成几 MB 的 0 字节空洞 —— 文件看着大小正常,里面有洞,日志内容是断的

> 关掉上限之后 `Logs` 会一直长(一局约 2.5MB),偶尔清一下旧的 `Hearthstone_*` 目录就行。

> 两个配置文件都写好之后，重启一次炉石就生效。

装到别的盘时,在扩展设置里填「炉石安装目录」,或者直接把「Power.log 路径」指到具体文件。

## 她会说什么

四种事件推给你,都是**事实通知**不是命令,说什么由她自己的口吻决定:

| 事件 | 触发 | 投递 |
|---|---|---|
| `hearthstone.game.start` | 一局开始,双方职业已知 | flush |
| `hearthstone.turn` | 轮到你行动 | debounce |
| `hearthstone.alert` | 见下表 | flush |
| `hearthstone.game.end` | 分出胜负 | flush |

告警分两组,而且**每条都带紧迫度**(推送时渲染成〔提醒〕/〔紧张〕/〔危险〕),她据此换口吻:

| 组 | 告警 | 紧迫度 |
|---|---|---|
| 阈值 | 残血 · 被铺场 · 空场 · 手牌打空 · 牌库告急 | 〔紧张〕 |
| 阈值 | 濒死 · 对面够斩杀 · 疲劳 | **〔危险〕** |
| 阈值 | 对面残血 · 你够斩杀 · 水晶溢出 | 〔提醒〕 |
| **转向** | **一回合掉 8 血以上**(被压住了) | 〔紧张〕 |
| **转向** | **场面反被压制**(刚才还压着) | 〔紧张〕 |
| **转向** | **差 1–5 点就能杀**(逼近斩杀) | 〔提醒〕 |
| **转向** | **对手手牌攒到 8 张**(可能在等连招) | 〔提醒〕 |

告警一局内同类只报一次,同一批里的几条会合成一条送过去,不会把她刷成一串短消息。

## 她走路为什么不再避开你的手牌

0.6.0 之前，扩展每次启动会往宿主桌宠包里补一套「手牌禁行带」：她走进屏幕底部中间那一段，
就蹲下、起跳、横跨到牌区另一头。那条路是**改写宿主安装目录**，市集把这类扩展一律拉黑
（`cortico-extensions#659`），所以整套补丁删掉了。

**这条功能靠形象包补不回来。** 触发条件是「她的位置落进禁行带」，而 `pet.x` 那套走位逻辑
（`skip` / `SKIP_EDGE` / `leapTo`）整段住在宿主 `web/kit/body.js` 里 —— 形象包只能拿到
`frame.gesture` 自己画姿态，改不了位置，也拿不到禁行带。所以：

- **蹦迪、律动这类「原地动作」** → 可以做成形象包（宿主 `act()` 的 `default` 分支会把名字交回来）
- **避开手牌这类「走位行为」** → 只能向 [Pal-AI-Lab/Coopanion](https://github.com/Pal-AI-Lab/Coopanion/issues)
  提需求，让宿主自己开一个接口

想要前者，这个扩展**自带**「律动版大肥鱼」——`assets/figure-groove/` 里就是它（底座是 Pal-AI-Lab
的 `whale`，加了 12 个动作），启动时自动装到 `<部署>/data/figures/groove/`，你只需要去换装页选它一次。
形象包没有地方发（市场只收 world / bot / provider），所以只能跟着扩展走。后者目前没有合法实现路径。

## 表情

每条事件带一个**桌宠表情 id**,她说话时用 `pet_say` 的行内标记 `<id>` 插进气泡里。

```
告警:  〔危险·scared〕对手当前场攻合计 11,我的生命值加护甲是 7——他下回合够得着斩杀。
回合:  建议[determined]:危险:…
```

`·` 后面、方括号里就是表情 id。用的是桌宠立绘包自带的那套词(coo 和 whale 两个包**完全相同**的 19 个):

`neutral` · `happy` · `wink` · `love` · `shy` · `surprised` · `angry` · `sad` · `sleepy` · `thinking` · `smug` · `pout` · `worried` · `determined` · `flustered` · `scared` · `excited` · `cry` · `confused`

**分配原则是「脸比嘴快」**:

| 局面 | 表情 |
|---|---|
| 濒死、对面够斩杀 | `scared`(瞪眼冒汗) |
| 残血、被铺场、空场、牌库告急 | `worried` |
| 一回合掉 8 血、场面被翻 | `flustered`(> < 满脸通红) |
| 疲劳 | `sad` |
| 够斩杀 | `excited`(星星眼) |
| 对面残血、差一点就能杀 | `determined` |
| 对手囤牌、手牌打空 | `thinking` |
| 水晶溢出 | `smug` |

**普通回合不换表情。** 每回合变一张脸不叫有反应,叫抽风;真正会被记住的是转折点。这条写进了她的提示词——事件里没给 id 就保持原样。

表情写错成不存在的词**不会报错,只会静默什么都不发生**,所以测试里有一条专门核对每个 id 都在上面那 19 个里面。

## 推荐这回合怎么打

`hearthstone_advice` 回执分四块,前三块是**事实**,最后一块是**机械排序**:

| 块 | 内容 | 来源 |
|---|---|---|
| 【手牌】 | 每张牌的卡名、实际费用、类型、摘要(身材 / 伤害 / 加攻 / 关键词)。能打出的标 `*` | `src/data/cards.json`(8328 张可收集牌) |
| 【斩杀线】 | 场面 + 手牌直伤 + buff,过墙后剩多少 | `planLethal()` |
| 【能做的交换】 | 每个随从打每个敌人的结果:换不换得掉、谁死、我掉多少血 | 同时结算模拟 |
| 【机械排出的候选】 | 按固定规则排:斩杀 > 避死 > 有利交换 > 群体伤害 > 立即冲击 > 铺场 | 阈值判断 |

**卡名三级兜底**:主卡表(可收集牌)→ 直伤表 → 加攻表。衍生牌(比如 `VAC_917t` 防晒霜)只在这两张小表里,主卡表查不到时靠它们补;三张都查不到就老实显示 `cardId`,不猜效果。

**摘要(第 3 位)是怎么来的。** 8328 张可收集牌,每家都有一句压缩效果:`伤害5群随从`、`吸血 伤害8群随机随从 召唤`、`3/3 圣盾 亡语`、`奶4`、`变形`、`获取3`。

提取是正则,不是 LLM —— 数字要准,延迟要零。踩过的坑:

| 坑 | 后果 |
|---|---|
| 数字前缀只兼容 `$` | 漏掉所有 `#N` 写法:`真言术：耀` 的「恢复 #4点生命值」一直没被读到 |
| 只认「造成 N 点伤害」 | 变形、复制、获取、交换、摧毁、弃手牌全漏 |
| 没有兜底 | **2347 张法术里 1395 张摘要完全空白** —— 她只看得见牌名 |

现在:**法术摘要空白 0 张**,中位长度 5 字。兜底只给法术、限 28 字 —— 随从的身材(`3/3`)已经够判断能不能换,硬拼一段原文会变成「3/3 在你的回合结束时 如果本随从未攻击 &抽两张牌」这种噪音,而它占的是最贵的那点空间。

**几个刻意的取舍:**

- **不替她做决定。** 回执给事实和候选,推荐由她自己下 —— 牌面效果的取舍、对手可能捏着什么,不是代码能算的
- **不猜对手手牌。** 日志里对手手牌是空的(不揭示就没有 cardId),硬猜只会给一个看起来精确、实际是编的数
- **单随从换不掉 ≠ 解不了。** 3/3 + 2/3 合力能解 4/5,单独算(`combinedTrades`)并**按顺序模拟**:先打的把血磨下去、后打的才够得着,中间会死人 —— 不能把「两个换一个」说成「轻松解掉」
- **手上有突袭/冲锋牌单独点出来。** 那等于当回合多一份解场或打脸手段,但算不进斩杀线

重新生成卡名表:

```bash
node tools/build-card-table.mjs <cards.json> src/data/cards.json
```

## 每回合自动给建议

`hearthstone.turn` 事件里直接带一行 `建议:`,她收到就能开口,不用再调一次工具。

```
第 9 回合,轮到我。我 21 血、手牌 6 张、5/5 水晶;对手 13+4 血,场面 2 个(攻 3/血 0 合计)。
建议:危险:对面场攻 9,我只有 21 有效血…… 换掉 3/3 嘲讽,能削 3 点。
```

**只有一句,不铺开。** 铺开她就会照着念,那是播报不是陪打;细节仍在 `hearthstone_advice`。

建议的优先级:能斩杀 → 会不会被打死 / **差 5 点以内就死** → 有干净的交换就换 → 按费出牌 → 什么都做不了。

**差 5 点以内算「贴着斩杀线」**,和「马上要死」同等对待。这个阈值不是拍的:对面手里多半还有牌,一个 2 费随从 2–3 点、一张直伤 3–6 点,留 5 点余量等于把「对面有牌」算进去。

解不掉的时候**必须给一个能做的事**,不能只报噩耗。判据是这张牌能不能吃掉对面一次攻击——圣盾、嘲讽、召唤、亡语的算,纯身材不算(3/3 挡不住 7/7)。

0 费牌不进「按费打」:它不占费用、随时能打,放在这回合的推荐里就是噪音(实测曾推荐「按费打:硬币」,等于让他白扔一张凑费牌)。

配置里「回合事件里带建议」可以关掉,关掉就只报局面。

### 核心牌:别把 combo 组件当普通随从打出去

机械规则只看得懂「费」和「攻」。4 水晶手上那张 3 费核心牌,账面上就是「按费打正好」—— 可它值钱的地方在等配合,不在站场。

设置页「我的牌组 → 核心牌」里填进去(逗号分隔,牌名或卡牌 ID 都行),之后:

- **有别的牌能打** → 它不进推荐位,末尾补一句「X 是你标的核心牌,这回合先留着等配合」
- **能打的只剩它** → 不再写「按费打」,改成「配合没到位就别拆」;如果场面上还有攻击力,那句话会顺便说明这回合让随从去干活,而不是叫他空过
- **三个通道一致** → 手牌表、工具回执、喂给模型的摘要里都会标「核心牌」。只改一处是不够的:她会从另一个通道把这张牌重新捡回来推荐
- **斩杀时例外** → 打出去这回合能赢就打,不留

改完立即生效,不用重启。

> 匹配是**去空白后包含**:填「德雷阿佳丝」能命中全名,填 `BE_703` 也行。单字不放开 —— 写个「龙」会命中半个牌库。

### 哪一方是你

默认自动认:靠开局那条 `CURRENT_PLAYER=1` 的 playerId 与 BattleTag 配对,再用「手牌只有自己能看见」交叉验证。

万一还是把你和对手说反了(血量、胜负全反),设置页「对局日志 → 哪一方是你」可以强制指定 `1` 或 `2`,下一批日志就生效。

> 这一项以前是坏的:声明了、默认值有、界面也在,但从来没接到解析器上 —— 改了什么都不发生,还不报错。2026-10-24 接上了。

### 三个坑(改了三版才定)

1. **两句话必须来自同一份快照。** 一开始局面取「回合开始那一刻」、建议现取当前状态,结果文字说「对手 9 血、场面 1 个」,建议说「对面场攻 9」—— 自相矛盾。
2. **回合刚变那一瞬,资源还没刷新。** 上一回合的消耗(`RESOURCES_USED`)还没归零,拿这份状态算建议会得出「没牌可打」,而他手上八张牌。判据不能只看 `mana > 0` —— 实测抓到过 `mana=1` 的过渡帧。现在的判据是**水晶上限够不够这一回合该有的值**:我方第 k 个回合就是 k 水晶,全局回合数是 2k(对手先手)或 2k−1(我先手),所以期望上限 = `ceil(turn / 2)`。不够就等下一批再算。
3. **不要靠标签回调排队。** 原来在 `CURRENT_PLAYER` / `STEP` 回调里攒回合点,那条路依赖 `isMyTurnNow()`(按玩家名分桶)判断轮次,长时间运行后会失准,整局一个事件都排不出来。现在改成由**每批结束时的快照**驱动:快照里的 `isMyTurn` 和建议用的是同一份数据,不会再自相矛盾。

## 她自己的打法

第一次启动会建一份 `hearthstone-style.md`（跟存档同一个目录），第一人称，四节：

| 键 | 写什么 |
|---|---|
| `who` | 我在牌桌上是什么人 —— 话多话少、先说结论还是先讲风险、看到臭手会不会直说 |
| `push` | 我倾向这么打 —— 激进 / 控制 / 贪 |
| `dislike` | 我看不惯的打法 |
| `unsure` | 还没想明白 |

**一开始是空的，这是有意的。** 空着说明她还没有立场。别替她填 —— 填进去的就是你的打法，不是她的。

整篇读进系统提示词，所以她开口之前偏好就在，不用临时查。**她只能一条一条加（`add`），不能整篇覆写** ——
这是全扩展唯一一个不可恢复的文件。你也能直接用编辑器改，格式就是 `- 一条`。

### 它只管两件事

1. **怎么说** —— 同一句「打脸,6 点」,可以是干巴巴报数,也可以带一句「这局面别磨」。
2. **先推哪条** —— 建议常常给好几条能打的路,机械排序只挑了其中一条。档案里有取向,就先推她那一条。

### 三条它管不了的红线

这三条写死在提示词里，**开关和档案都碰不到**：

- **算出有斩杀就必须说。** 不管档案里写着「我偏爱慢慢磨」还是「我不爱上脸」。这是这份档案唯一会真的害到人的地方。
- **建议里点出的风险必须转告** —— 0 攻带亡语的墙、能复生的随从、手里的群伤。换个说法可以，吞掉不行。
- **不许马后炮。** 立场要在出牌**之前**说。打完了才来一句「我就觉得该打脸」，那不是风格，是白拿便宜。

### 为什么门槛定得这么高

只在**明显的错判**上写：算出了斩杀没喊、解牌拍错目标、核心牌提前打了。日常小偏差不写 ——
这份档案要留的是最硬的几条，写成流水账三个月后自己都不想读。

**输了更要写，而且先写自己哪一步偏了。** 写不出才归到运气，但「写不出」和「不想写」是两件事。
只记赢的局，她最后会变成一个永远有理的牌友 —— 那种牌友没人喜欢。

一节最多 8 条、一条最多 60 字。满了不加，得先删。设置里有「允许她自己改打法档案」开关，
关掉之后她只能读，已有的照旧生效。

### 和另外几个的分界

| | 是什么 | 谁给的 |
|---|---|---|
| `hearthstone_advice` | 这回合能打什么、斩杀多少 | **算出来的** |
| `hearthstone_meta` | 这个职业怎么赢 | 联网搜的，**别人的结论** |
| `hearthstone_plan` | 这套牌靠什么赢 | 模型推的，**针对这一副牌** |
| `hearthstone-style.md` | 我信哪一套、我看不惯什么 | **她的** |
| `hearthstone-his-style.md` | 你实际怎么选 | **从你的对局里数出来的** |

## 按谁的思路陪打

面板上有一行「按谁的思路」，两个按钮：**她的** / **你的**。默认是她自己那份。

### 你那份是怎么来的

不是她猜的，也不是你写的 —— **从 `hearthstone-games.jsonl` 里数出来的**。每局那一行本来就记着
「这回合建议推了什么、你实际打了什么」，攒起来就能算：

- 按建议打的比例，以及**分胜负各是多少**
- 按回合段的分布（前 5 / 6–10 / 11 以后 —— 你是前中期听、后期自己来，还是反过来）
- 常玩的职业、各赢了几局
- **没按建议走的时候，你改打了哪几张**

每次打完一局自动重算，存在 `hearthstone-his-style.md`。那个文件分两段：
上面是数出来的（每次覆盖），下面 `## 他自己补的` 是你说的（**永远不会被覆盖**）——
「这局在试新卡组」这种事记录里看不到，只有你知道。让她记也行（`hearthstone_his_style`）。

### 两件必须知道的事

**一、样本不够它会说实话。** 不到 5 局 / 20 个决策点，文件里就写「样本还不够，别当规律」；
5–9 局写「偏少，只能当个大概」。别指望打了三局就能总结出你的风格。

**二、短得不像真对局的记录会被跳过。** 判据是一局的时长：少于 60 秒的整条不算 ——
那是测试、回放，或者日志里同一局的重复结束点。跳过几条会写在文件里。
（这条是踩出来的：某台机器上 50 条记录里有 45 条是测试写入的，每局 0.008 秒，
局数和决策点数都骗过了闸门，于是一本正经地报了个「采纳率 33%」。）

### 切到「你的」之后，什么变了什么没变

**变了**：立场、措辞、以及几条路都合法时先推哪条。她读的是你的习惯，会用「你」说你，不会说成「我」。

**没变**（三条写死，两个开关都碰不到）：

- 算出有斩杀就必须说 —— 不管你的档案里写着什么
- 建议点出的风险必须转告
- 不许马后炮

还有一条只在你这边生效的分寸：**数出来的是事实，不是命令。** 「按建议打 40%」不等于
「你该少听建议」，「赢的局采纳率高」也不等于「听建议就能赢」—— 那只是相关，赢的那几局
或许只是建议刚好也对得上。

## 她记得你最近打得怎么样

每局打完往 `hearthstone-games.jsonl` 追加一行，留最近 50 局。一行里有：胜负、回合数、双方职业、
终局血量、**全程最低血量**，以及**每回合她推的牌和你实际打出的第一张**。

- 最后那个 `lowHp` 是特意加的：「30 血零封」和「2 血翻盘」同样是「胜 · 17 回合」，光看结果分不出来。
- `turnLog` 是为了复盘能对比 —— 她推的和你选的是不是同一条路。只存每回合第一张，一回合的路线基本由它定。
- 她能读到最近 5 局的摘要（`{{hs.recent}}`），问「我最近打得怎么样」不用你翻文件。
- 想看某一局具体怎么走的，还是用 `hearthstone_last_game`（那份是完整时间线）。

**为什么不复用会话记录**：`session-main.jsonl` 会轮转 —— 实测打完三把之后只剩最后半把，
前两把的字一个不剩。归档是追加式的，谁都不会把它整份覆盖掉。

## 模型第二意见（默认关）

**默认是关的**,理由很直接:它在 `hearthstone_advice` 里同步 `await`,打开之后你点一下要**多等 3–7 秒** —— 体感就是「卡」。而机械规则(斩杀、交换、墙、疲劳钟)已经够硬,再要一段独立判断的边际价值抵不上这几秒。

想开就在配置页打开 `llmAdvice`。打开后末尾会多一段 `【模型的判断】`,来源是 DeepSeek(OpenAI 兼容格式,超时压到 3 秒 —— 宁可拿不到,也别堵着)。

**它补的是规则算不出的那一层**:「这回合忍一手,下回合斩杀」这种多回合规划。规则能算清每个数字,但不会下这种判断。

**密钥从哪来**:框架只把模型客户端交给 Persona(她本人),World 拿不到 `llm`,只拿到 `secret()`。所以这里自己发 HTTP,密钥读部署目录的 `.env` —— 也就是设置界面存 key 的地方。按顺序找:

```
CORTICO_HEARTHSTONE_DEEPSEEK_API_KEY   ← 本扩展专用槽位
CORTICO_BROWSER_DEEPSEEK_API_KEY       ← 复用 browser 扩展已经填过的
DEEPSEEK_API_KEY
```

只要其中有一个,就能用,不用重填。

**为什么默认关**:事件推给她之后,她本人就是模型,会用自己的判断润色 —— 再调一次等于让同一个问题排队等两个模型。这就是「卡」的来源。

**失败就退化,不报错**:没密钥、超时(3 秒)、非 200、返回结构不对 —— 一律只给规则结果,末尾不会出现那段。日志里记一条 `模型第二意见没拿到`。

配置项:`llmAdvice`(开关)、`llmModel`(默认 `deepseek-chat`)、`llmBaseUrl`(默认 `https://api.deepseek.com`,兼容任何 OpenAI 格式端点)。

## 词条算到哪一步

**进数值(影响斩杀线和交换判断):**

| 词条 | 怎么算 |
|---|---|
| 嘲讽 | 过墙要按它消耗攻击力;交换时优先度加权 |
| 圣盾 | 过墙先破盾(占一次攻击);我方圣盾吃反击不掉血;群体伤害不把带盾随从算进清场 |
| 风怒 | 攻击次数算两次 |
| 冻结 | 对面被冻结的随从不计入下回合威胁 |
| 不能攻击 | 当回合不能动的随从不算进斩杀 |
| 剧毒 | **一刀致死,与血量无关**;过墙时剧毒一刀解任意血量的嘲讽;被剧毒反咬必死 |
| 法术伤害 +N | 场上随从的 `SPELLPOWER` 汇总后**加到每条直伤上**(火球 6 → 场上 +1 时算 7) |
| 无视嘲讽 | 我方有这类随从(如凯恩·日怒)时,过墙这一步直接跳过 |

**在交换里提示、但不改斩杀数字:**

| 词条 | 提示什么 |
|---|---|
| 复生 | 「它复生,死了还会留 1 血」,并降低这一手的评分 |
| 亡语(带伤害) | 「它亡语还会打 N 点」,评分下调 |
| 吸血 | 「我吸血,能回 N 血」,评分上调 |

**只提示、不进数值:** 突袭/冲锋。它们要从手牌打出去、还要挑目标,和场上随从不是一回事,只在建议里单独点一句。

**进数值、但要过两道筛:** 战吼伤害。判据是「前提确定满足」(手上有武器、头上挂着光环、场上没有别的随从…)且「能打到脸」(卡面不是只打随从)。两条都过的才逐张计入斩杀线 —— 同名两张各算一次。前提不满足或判不了的,只在建议里写一句「要满足 X 才有 N 点」,不进这个数。

**明确不算:** 光环提供的属性加成(日志里的 ATK 已经是加成后的实际值,再算一遍就是重复计算)、潜行、免疫、沉默、复制类。

数据来源:法术伤害来自日志的 `SPELLPOWER` 标签;战吼/亡语伤害、无视嘲讽来自卡表第 5 位的结构化标签(`b3 d2 s1 t`),由 `tools/build-card-table.mjs` 从卡面文本提取,共 403 张牌有标记。

**为什么不接大模型算这些**:`mechanics` 和"造成3点伤害"这种文本是结构化的,正则提一遍就够准;换成每回合一次 LLM 请求,换来的是延迟和不确定性 —— 算错一次比慢一秒糟得多。LLM 更适合放在"读懂一段自由文本"的地方。

## 竞技场选牌

`hearthstone_draft` 给的是:每张候选的解析(费用/身材/效果摘要)、一个**启发式机械分**、当前牌组的曲线和缺口、机械排序。

**候选牌必须由你念给她 —— 日志里没有。** 炉石的 `[Arena]` 通道存在,但选牌那三张不进文本日志:同样读日志的 Arena Tracker,它的文档里写的是「选牌要截图识别、选完把鼠标移开才能读下一张」。所以这里不做「自动读取三个选项」这种假装能做的事。

**机械分怎么算**(不是天梯榜,是平局参考):

| 部分 | 算法 |
|---|---|
| 基准 | 随从/武器 6 分,法术 3 分(法术占一张牌、换一次节奏) |
| 身材 | `攻击 + 生命 − (2×费用 + 1)`,即**超出同费白板多少**。2 费 2/3、4 费 4/5、6 费 6/7 都是 0 |
| 关键词 | 圣盾 +3、剧毒 +3、冲锋 +2.5、突袭 +2、风怒 +2、嘲讽 +1.5、亡语/吸血 +1.5、冻结 +1.5 |
| 效果 | 群体伤害 `2.2×伤害`、单体直伤 `1.4×伤害`、抽牌 `2×张`、消灭 +5、+N/+M `0.9×点数` |
| 费用折价 | 6 费 ×0.95、7 费以上 ×0.9 |
| 曲线 | 牌组缺这一档 +1.2,已经堆满 −1 |

故意不做的:不算职业搭配、不算环境、不猜对手。那些只有她的判断能给。

**记录**:`pick` 记下实际拿的牌(存在 `data/hearthstone-arena.json`),`reset` 开新一轮。不记曲线就会一直差一张。

```json
// 工具参数示例
{ "options": ["火球术", "石拳食人魔", "银背族长"], "pick": "火球术" }
```

## 扩展页:一块面板 + 两组配置

**陪打面板**(默认展开)是日常只用这一个:

- 一行状态:第几回合、轮到谁
- 五个数:我 / 对面 / 水晶 / 对面场攻 / 手牌
- **一个按钮「让她看这回合」** —— 非自动模式(`mode=quiet`)下这就是唯一的问法,不用去聊天框打字
- 一行建议,按类型上色:危险红、能斩杀绿、按费打蓝
- 三个开关:她自己会开口、轮到我时提一句、关键节点开口

点按钮做两件事:面板立刻显示机械建议(零延迟),同时推一条 `hearthstone.ask` 给她,她用**回答**的口气说一两句 —— 不是解说口气。这条不受 `quiet` 限制:`quiet` 关的是「她主动开口」,而这是你在问。

**配置页**只剩两组,都是「一次配好」的:接入(`logPath`、`installDir`、`localPlayerId`、核心牌)与高级(残血线、被压场线、轮询间隔、模型第二意见、模型名)。日常开关都在面板上,别再往设置页堆。

面板实现:浏览器 bundle `webui/panel.js` + `webui/panel.css`,由 `package.json` 的 `cortico.webUiClient` / `webUiStyle` 声明,数据面是 `world.webUi().invoke(panel, method, args)`,只有三个方法:`status` / `ask` / `auto`。

> 资源 URL 是 `/assets/extensions/<包>/<版本>/panel.js`,**没有内容 hash**。改了 bundle 要升 `package.json` 的 `version`,否则浏览器按旧 URL 缓存一年,你看到的还是老界面。

## 激活失败怎么办

如果点激活报错「**World hearthstone 与 World hearthstone 的工具撞名**」,那不是配置问题,是上一次激活半途失败留下的幽灵实例:World 已经进了挂载表,但 `slot.mounted` 没被置上,于是之后每次激活都拿新实例跟这个幽灵比工具名,必然撞。

成因是本扩展早期版本把提示词模板路径拼到了 `WorldContext.packageDir`(那是 **bot 的**包目录,不是扩展自己的),框架重建系统前缀时 `readFileSync` 该路径抛 ENOENT,激活流程就断在中间。现在改成按 `import.meta.url` 定位,已修复。

**遇到时的解法**:重启 Coopani(清内存),再点一次激活。点一次就等它走完,别连点——中途再点会加剧状态错乱。

## 斩杀线怎么算

三件事一起算:

- **场面**:随从攻击力 + 武器 + 英雄攻击力。**武器和英雄攻击力是同一个数**,不能相加(装备武器后英雄 ATK 就等于武器攻击)
- **过墙**:对面有嘲讽时,攻击力得先拿去解墙。一次攻击用掉就没了 —— 9 攻打 2 血嘲讽剩 0,不是剩 7。圣盾嘲讽要两次攻击(破盾 + 打血)。按「小的先撞、刚好够的优先」贪心排,接近真人打法
- **手牌**:按水晶挑出打得起的直伤法术和加攻击的 buff。buff 需要有能攻击的随从接,否则不算

数据来自 `src/data/damage-spells.json`(198 张直伤)和 `src/data/buff-spells.json`(312 张加攻击),由 `tools/build-*.mjs` 从 HearthstoneJSON 的 zhCN 数据生成。重新生成:

```bash
node tools/build-damage-table.mjs <cards.json> src/data/damage-spells.json
node tools/build-buff-table.mjs   <cards.json> src/data/buff-spells.json
```

**收录标准是保守的** —— 只收能直接打脸的单次直伤:

| 排除 | 原因 |
|---|---|
| 「对一个随从造成…」 | 碰不到脸 |
| 「对所有…」「每个…」 | 群体,不是斩杀手段 |
| 「随机」 | 落点不确定 |
| 「两次」「两遍」「各造成」 | 伤害结构不同 |
| 非可收集且伤害 ≥ 10 | 冒险/乱斗 Boss 牌,正常对局拿不到 |

所以报出来的数是**下界**:真实伤害可能更高,不会更低。

**没算进去的**:冲锋随从召唤、前提不满足/判不了的战吼、法术伤害加成、无视嘲讽。这些都在回执末尾的「注意」里写明。

## 已知限制

1. **「我是哪一方」是自动认的**,靠开局那条 `CURRENT_PLAYER=1` 把 BattleTag 和 playerId 绑起来,再用「手牌只有自己能看见」交叉验证;最后还有一道血量反证(我 0 血不可能赢)。万一还是说反了,到设置里把「哪一方是你」改成 1 或 2 强制指定 —— 那一项直到 2026-10-24 才真正接上线。
2. **职业靠英雄卡牌 id 前缀认**(`HERO_08` → 法师,皮肤同理)。认不出的显示为空,她会说「职业未知」。
3. **卡牌名字来自日志里的 `name=` 字段**,中文客户端给中文名。日志没揭示的牌(对手手牌)只有数量。
4. **日志比画面晚几百毫秒**,极快的一瞬间可能漏掉——她这时候应该说「没看到」,而不是猜。
